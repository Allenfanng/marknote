# MarkNote v1.1 Design Spec

## Overview

v1.1 fixes 5 known issues from v1.0 and delivers a significant UI overhaul. The goal: transform MarkNote from a functional prototype into a polished, professional Markdown editor.

## Problem List (from `1.0版本存在的问题.txt`)

1. Theme switching broken — main editor area stays dark in light mode
2. No file drag-and-drop support
3. Toolbar layout issues — blends with background, needs Word-style top layout with better UI
4. No source code view (Typora-style toggle)
5. App icon needs to use `marknote_v1.1.png`

## Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Toolbar style | Single-row lightweight (Notion/Obsidian style) | Markdown editors don't need Word-level complexity. Single row covers 99% of operations without impacting startup speed. |
| Source code mode | Full-page toggle | Fits lightweight editor positioning. Split-pane is a separate feature for a future version. |
| Visual style | Restrained neutral (Notion/Linear style) | Gray-white base, thin borders, low saturation. Professional, easy on the eyes for long editing sessions. |

## Feature Details

### 1. Theme System Fix

**Root cause:** Only `[data-theme='dark']` Milkdown CSS variable overrides exist. The `classic-dark.css` styles leak into light mode.

**Fix:** Add explicit `[data-theme='light']` Milkdown variable overrides in `App.css`:

```css
[data-theme='light'] .milkdown-classic {
  --crepe-color-background: #ffffff;
  --crepe-color-on-background: #1a1a2e;
  --crepe-color-surface: #f8f9fa;
  --crepe-color-on-surface: #1a1a2e;
  --crepe-color-surface-variant: #e9ecef;
  --crepe-color-on-surface-variant: #6b7280;
  --crepe-color-primary: #4a6fa5;
  --crepe-color-on-primary: #ffffff;
  --crepe-color-outline: #d1d5db;
  --crepe-color-border: #e5e7eb;
}
```

All toolbar and titlebar colors use CSS variables for consistent theming across the entire window.

**Color palette:**

| Variable | Light | Dark |
|----------|-------|------|
| `--bg-primary` | `#ffffff` | `#1e1e1e` |
| `--bg-secondary` | `#f8f9fa` | `#252526` |
| `--bg-hover` | `#e9ecef` | `#3c3c3c` |

### 2. File Drag-and-Drop

**Implementation:** Custom `useDragDrop` hook in `App.tsx`.

- `dragover`: prevent default, show overlay
- `drop`: extract file path from `event.dataTransfer`, validate `.md`/`.markdown`/`.txt` extension, invoke `read_file` to load
- Visual feedback: semi-transparent overlay with "Drop to open file" text

**Tauri v2 note:** File drag-in requires `tauri-plugin-drag` or `dragDropEnabled` configuration in `tauri.conf.json`. Need to check Tauri v2 drag API documentation during implementation.

### 3. Toolbar

**Groups (separated by dividers):**

| Group | Buttons | Icons (Lucide) |
|-------|---------|----------------|
| File | New, Open, Save | `FileText`, `FolderOpen`, `Save` |
| Format | Bold, Italic, Strikethrough | `Bold`, `Italic`, `Strikethrough` |
| Heading | H1, H2, H3 | `Heading1`, `Heading2`, `Heading3` |
| Block | Bullet list, Ordered list, Code block, Blockquote | `List`, `ListOrdered`, `Code`, `Quote` |
| Insert | Link, Image | `Link`, `Image` |

**Behavior:**
- Each button shows tooltip with name and shortcut on hover
- Buttons execute Milkdown commands via the editor instance (format buttons) or invoke file operations (file buttons)
- Active state highlighting (e.g., bold button lights up when cursor is in bold text)
- Toolbar is always visible in both WYSIWYG and source mode (source mode disables format buttons)

**Editor instance access:** `Editor.tsx` needs to expose the Crepe instance (or a command API) to `App.tsx` so toolbar buttons can dispatch ProseMirror transactions. Options:
- Use `useImperativeHandle` + `forwardRef` to expose a command API
- Or use a shared ref/context

The imperative handle approach is cleaner — Editor exposes methods like `execBold()`, `execItalic()`, `execHeading(level)`, etc.

### 4. Source Code View

**State:** `viewMode: 'wysiwyg' | 'source'` in `App.tsx`.

**Behavior:**
- Toggle via toolbar button (icon: `</>`) or `Ctrl+/` shortcut
- WYSIWYG → Source: get markdown from Milkdown listener state, render in `<textarea>`
- Source → WYSIWYG: pass textarea content as `defaultValue` to `Editor` (triggers re-mount via `key` prop)
- Content syncs bidirectionally on toggle
- In source mode, format toolbar buttons are disabled (grayed out)

**Textarea styling:**
- Monospace font (`JetBrains Mono` or `Fira Code` with system fallback)
- Line numbers (optional, can defer to v1.2)
- Full editor area, same padding as WYSIWYG
- Respects theme colors

### 5. App Icon

3. Verify `tauri.conf.json` icon paths match generated files

### 6. TitleBar Refactor

**Before (v1.0):** Filename + dirty dot + [New] [Open] [Save] [Theme]

**After (v1.1):** Filename + dirty dot + [Theme toggle] [Source toggle]

File operation buttons move to the toolbar. The TitleBar becomes a slim, clean header.
